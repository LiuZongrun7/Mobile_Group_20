# ModelPilot 完整前端设计说明

版本 V7，2026-09-29。此稿承接已确认的三项变化：首页直接提问、项目包含多个对话、同一对话逐条选择模型。项目正式展示名称为 ModelPilot。本版重点完善 Insights。

## 1. 产品在界面中的表达

用户先面对问题、材料与结果。模型选择是输入区的一项控制，用量统计提供花费反馈与预算控制。用户不会因模型变化而进入另一个聊天空间。

顶层导航采用 Chat / Insights / Explore / Me。Chat 是默认入口；Explore 收纳社区、游戏和产品更新。进入对话、明细、设置等二级页面后隐藏底部导航，使用返回按钮。

### 核心对象

| 对象 | 用途 | 展示位置 |
| --- | --- | --- |
| Project | 组织多个相关对话，放置显式共享的文件和说明 | 首页文件夹、项目页 |
| Conversation | 保存一条完整话题及其独立历史 | 项目子列表或未分组列表 |
| Message | 一次提问或一次回复，关联附件与产物 | 对话正文 |
| Model mode | 下一条消息使用 Auto 或指定配置 | 输入框下方的选择器 |
| Actual model | 某条回复实际采用的模型 | 回复底部的来源行 |
| Usage record | 模型和工具产生的用量及费用 | Details、Insights |

项目不绑定模型。对话列表显示 `Last · Model …`，表示最后一条已完成回复实际使用的模型。它是历史标签，不是下一条消息的模型设置；选择器仍独立显示 Auto / 手动模式。没有完成回复的新对话显示 No replies yet。处理中、失败或被停止的新请求不覆盖已有 Last 标签。

加入同一个项目不等于自动共享所有聊天记录；共享范围由项目文件、项目说明和明确设置决定。

## 3. Chat 的交互规则

### 首页输入与分组

首页输入框采用两行布局：上方文字，下方依次放置附件、模型模式、项目归属和发送。固定在底部导航上方，不随列表滚走。

输入框默认 Auto / No project。用户可直接发送，新对话随之创建；选择某个项目后，新对话归入该项目。点击项目行的加号直接新建项目内对话；点击已有对话继续它的历史。点击项目名称进入项目详情，左侧箭头独立控制折叠。

项目名称与对话标题过长时截断，完整名称可在详情或重命名界面查看。首页每条对话采用“标题与时间 + 最近模型标签”两行结构；摘要留在项目详情等空间更充足的位置，避免为新标签额外堆叠小字。模型标签使用“品牌图标 + Last · 具体模型名”，例如 DeepSeek 鲸鱼图标与 DeepSeek V3.2。品牌图标不是版本号，因此必须同时显示具体模型名；蓝 / 紫 / 青绿仅为辅助色。未知配置保留名称并使用通用图标；已知图标加载失败则回退到首字母。

已有对话通过菜单移动项目、重命名和导出。项目内的 Chats / Files / Instructions 是三种资料组织方式，不能让用户误以为每个项目都绑定一个模型。

### Auto 与手动选择

Auto 表示每次发送新消息重新作出选择。连续两条消息可能使用不同模型，也可能使用相同模型；不承诺每次一定切换。

手动选择持续作用于当前对话的后续请求，直到再次选择或切回 Auto。首页草稿的选择会成为新对话的初始模式，不改变其他对话设置。历史回复的模型来源不受当前选择影响。

模型可用性根据实际“模型 + 工具 + 附件”组合计算。示例配置的展示名分别为 DeepSeek V3.2、Claude Sonnet 4.6、GPT-5.5；内部 A/B/C 标识仅用于原型数据映射，没有接入真实 API。选择器与可用模型页标明 Demo。图像理解与图像编辑分别处理，本稿仅为 GPT 配置启用示例图片工具，不代表其他模型天生不能接入同类工具，也不是品牌能力排名。

接入后统一维护模型注册表：稳定 model ID、provider、display name、logo asset、能力与工具配置。每次请求返回后，将实际使用的 model ID 存到该条回复；所有 Last 标签与来源行从这条记录读取。不要从用户当前选择器推断历史模型，也不要靠模型名字的模糊字符串匹配品牌。新品牌缺少图标时仍能显示名称，不能阻止回复展示。

如果用户手动选择的模型不能处理新附件，保留草稿并要求选择适用配置或 Auto。失败、余额不足、暂不可用等情况不得静默更换手动模型。Auto 模式下的降级若影响能力或产物，应说明变化。

### 多模态任务

当前例子属于 Campus event / Event materials：上传活动 PDF，总结要点；随后上传海报，修改背景。两步都留在同一对话，图像结果显示预览、保存和继续修改入口。

真实 Android 上传流程使用系统文件或图片选择器。文件卡片显示类型、名称、体积或页数；上传前能移除，上传中有进度，失败可重试。系统权限只在需要时请求。原型用示例附件直接进入完成状态，避免在设计稿中接入真实文件处理。

回复只显示结果和一条简短来源行，例如 Claude 图标与 `Auto → Claude Sonnet 4.6 · Details`。图片任务附加 Image tool。Token、具体费用、路由原因、工具调用进入 Details。任务包含多个模型调用时，明细逐项记录；主界面可显示主要回复模型，不能把工具执行模型冒充为全部调用。

编辑结果与原图关联，继续修改默认引用上一次结果。当前交互原型用示例图片演示流程，真正接入时需区分原图和每一次编辑版本。

### 记忆与状态

记忆页显示可编辑摘要及上下文来源。默认使用当前对话的近期消息、摘要、当前附件和明确共享的项目说明；不混入其他对话的全部历史。切换模型沿用同一上下文管理机制。

空白页只给一句提示和开始入口。处理中展示当前任务状态和停止操作。失败保留消息及附件，提供重试。预算阻止请求时保留草稿，并导向预算页。键盘出现时输入框保持可见，列表让出空间，顶层底部导航可暂时隐藏。

## 4. Insights 的信息层级

按“花了多少 → 花在哪里 → 怎样使用”组织单列页面。首屏为估算费用、Token / 模型调用数和预算；向下依次为每日趋势、模型 / 供应商分布、App 内活动日历、Auto 与工具、数据来源。两列布局只用于两个简短总量，不把完整图表压进半屏。

时间选择可切换本月、最近七日、上月和无数据月份；趋势可切换花费 / Token / 调用次数。模型分布可切换供应商及花费 / Token 占比。图表从零起算，每个视图只使用一种单位；日期详情既可点柱形，也可用前后日期按钮打开。模型和来源行进入对应筛选的用量记录。

活动日历只统计 App 内模型调用，显示范围内活跃天数及最长连续活跃天数，不把导入的历史记录当成用户在本 App 的活跃。Auto 占比分母为 App 内模型调用，而不是用户问题或任务数；工具次数与模型调用次数分开。统计口径、费用来源及缓存说明放进详情，首页不显示长说明。

本稿示例数据保持一致：

| 维度 | 示例 |
| --- | --- |
| 统计范围 | 2026-09-01 至 09-28，UTC+8；固定示例，不是实时账单 |
| 月费用 | ¥86.53 = 模型 API ¥82.33 + 工具 ¥4.20 |
| 月预算 | ¥140，使用约 62%，剩余 ¥53.47；不是账户余额 |
| 总 Token | 1,248,320，包含输入与输出 |
| 模型调用 | 432 次 = App 内 284 + 外部记录 148；不等于 432 个任务 |
| 来源 | Assistant ¥62.30 + External ¥24.23 |
| 模型费用（假设数据） | DeepSeek V3.2 ¥43.27 + Claude Sonnet 4.6 ¥25.96 + GPT-5.5 ¥17.30 |
| 最近七日 | 09-22 至 09-28，合计 ¥28.53 |
| App 内 Auto / 手动 | 218 / 66 次，Auto 约 77% |
| 工具使用 | PDF 提取 44 次，图片编辑 21 次；工具费用已计入总额 |
| App 内活动 | 28 天中活跃 23 天，范围内最长连续 8 天 |

上述数据从同一组日汇总样本计算，不分别硬编码成互相矛盾的图表。费用对比使用相等日期范围：9 月 1–28 日对 8 月 1–28 日，约降低 8%，不与整个上月比较。预算始终明确标为 September budget，切换七日或上月不改变它的月份和已用金额。没有记录的外部日期显示未知，不声称全账户零消费；没有可用数据的月份显示空状态，不补造趋势和百分比。

当前用量页展示“按日、模型和来源聚合”的记录，不把聚合行冒充单次请求。默认展开最近七个有记录的日期，导出包含当前筛选范围的全部示例行。App 内聊天交互不会改变这组固定统计样本。

最近记录列表不宣称覆盖整个账期。Provider 的实际账单是最终对账依据，估算值保持 Estimated 标签。图片服务按张、分辨率等产生的费用单列，不把所有成本强制换算成文本 Token。

预算和账户余额明确分开。提醒阈值与超额暂停由用户设置；真正实现时在请求前估算、请求后结算，长任务应支持费用上限。价格页需要价格来源、更新时间、计费单位及适用条件；未知值显示未知，不填零。原型所有金额明确标记为示例。价格中心的 Reference A/B/C 是独立布局示例，不表示三个真实模型的官方报价。

外部记录展示授权来源或导入文件、范围、更新时间和去重结果，不承诺自动读取各家官方私人聊天用量。重复导入不重复记账。

Android 现有 Room 日统计和图表依赖可复用，但现有来源枚举与本页“App 内 / 外部”不等价，Auto、工具和精确调用次数需要补充日志。Token 缓存字段需在适配层归一化：本稿的 cached input 是 input 的子集，不能再次相加。数据字典、费用防重和现有 Android 字段差异详见 [INSIGHTS.md](INSIGHTS.md)。

## 5. Explore 与 Me

Explore 顶部为 Forum 与 Tower defence 两张并列彩色入口卡片。考虑到论坛和游戏仍在开发，入口和对应页面都标明 Preview / In progress。点击进入独立页面，返回后仍可继续浏览动态。

入口下方为 News & updates。筛选项是 All / AI news / ModelPilot；采用统一的“左侧标题 + 右侧缩略图”列表，约 108×87px 的配图与最多三行标题并列，下方只留来源和绝对发布日期，不增加重复摘要。行间用分隔线，不再层层套卡片。图片未加载时保留布局与替代文字。

当前包含三条已核实的历史发布公告：OpenAI GPT-5.5（2026-04-23）、Claude Sonnet 4.6（2026-02-17）、DeepSeek V3.2（2025-12-01），以及 ModelPilot 设计更新。列表标明 Highlights，底部说明不是实时新闻流；不声称这些是最新模型。点击详情可看大图、图片来源、简短转述、原始发布日期和 Read original 官方链接。图片、新闻来源见 SOURCES.md。品牌新闻与本项目设计更新明确分开。

论坛沿用同一图文行组件，示例帖子使用工作区、Auto 路由、笔记三张原创矢量配图。每条帖子点击后展示其自身标题、图片与正文，收藏按帖子独立保存。示例帖子不虚构真实互动量；新帖可选本机 PNG/JPG/WebP 封面（上限 5 MB），仅在当前页面中预览，没有上传或真实发布。未提供封面时正常显示纯文字行，不强塞无关图片。

游戏沿用 TokenDefend 子功能名，游戏虚拟点数、真实 Token 和账户余额分别表述。原型的游戏按钮仅用于展示状态变化。

Me 按 AI & budget、Connections、Your data、More 分组。用量图表留在 Insights；这里不再重复累计 Token、余额、复杂会员或活跃图表。Auto 偏好可选择 Balanced / Save money / Faster replies，并限定可用配置。

连接页区分可用、未连接、测试失败等状态。实际密钥不在日志或导出中暴露。删除操作说明范围并确认；导出允许选择对话或用量。导出包含模型来源与数据来源，但不包含密钥。

主操作继续使用蓝色。紫色用于论坛与相关入口，青绿用于用量和游戏入口，暖黄色用于预算与游戏主按钮。模型历史标签也使用稳定的蓝 / 紫 / 青绿对应，不随列表顺序换色。浅色渐变集中在入口、封面和概览卡片，正文阅读区保持清晰。

颜色不是唯一状态线索。选中项有勾选和文字；错误有说明；不可用项归组并给出任务原因。弹层支持 Escape、键盘焦点约束和返回。Android 实现需适配 TalkBack、系统字体缩放与软键盘。

原型默认 393×852 逻辑尺寸，同时检查 360 和 320 像素宽度。较长页面通过纵向滚动展示，避免为了“一屏放完”持续缩小字号。长图只用于设计交接，不代表真实手机屏幕高度。

## 7. 设计稿与实现边界

本目录交付静态页面图、状态图和设计说明，不包含交互原型代码。前文描述的是拟实现的操作流程；图片中的按钮、弹层和示例回答不能直接操作，不代表真实服务已接通。

Android 实现仍需接入认证、持久化、流式回复、文件处理、Provider 适配、上下文管理、路由决策、计费记录和工具执行。界面里的成功、失败、用量和费用应由真实结果驱动，不使用设计样例冒充实际数据。

论坛与游戏属于附加功能，不改变以跨模型上下文、Auto / 手动选择和任务用量为核心的设计方向。
