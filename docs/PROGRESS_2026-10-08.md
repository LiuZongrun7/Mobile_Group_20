# ModelPilot progress and Auto routing implementation — 2026-10-08

## Current implementation

- Android Java/XML app: Chat, Insights, Explore/forum, Me; model calls are made from the phone using locally configured provider keys. The backend supports accounts and forum, not a universal usage relay.
- Chat: streaming responses, manual model changes, canonical shared context, compression memory inspection/editing, projects, image attachments, on-device text PDF extraction and opening original attachments.
- Data: Room chat/usage storage, answer/compression task-linked accounting, four token buckets, local monthly budget and currency settings, JSON/CSV/ZIP import/export.
- Community: account authentication, news/community lists, posts/images/comments/likes. Latest forum commit omitted DTOs, layout, reader and discovery module; this update restores those dependencies.
- Previous tower-defence functionality was deliberately removed by the team. This update follows the current ModelPilot direction.

## Added in this update

1. Auto checks actual retained task capabilities: an image anywhere in active context requires vision, including text-only follow-up questions. A PDF whose text has been extracted can use a text model.
2. Auto filters models against each provider's rendered input size and the context engine's safety/output reservation. Manual choices are never replaced; incompatible choices show a clear error before compression, and oversized requests stop before the answer call.
3. Candidate cost = estimated input × uncached input rate + estimated output × output rate. Unknown pricing stays unknown; no cache discounts or unsupported quality/speed claims are assumed. Large arithmetic and small-charge rounding are handled explicitly.
4. Persistent Auto preferences in the model picker: lowest estimated cost, larger context capacity, preferred configured provider with compatible fallback. Preferences affect the next Auto request only; compression keeps its existing independently selected model.
5. Model and route reasons still enter the existing task ledger with the new policy version. Cost presentation uses the existing Currency/FX settings, rather than a hard-coded RMB conversion.
6. Base64 image bytes no longer inflate textual token estimates. Images have a rough planning allowance (1,024 tokens per image), clearly identified in the route reason. It is not a provider tokenizer or a guaranteed image billing estimate.
7. Restored forum trending contracts, news cards, secure publisher reader with RSS-summary fallback, and deterministic headline-frequency/search helpers.

## Checks and boundaries

Windows backend setup now includes the required IANA timezone data (`tzdata`); it remains a conditional Windows dependency.

Run `gradlew.bat :app:testDebugUnitTest :app:assembleDebug` with JDK 17 or newer supported by the current Gradle version. Backend: `python -m pytest backend/tests`; RSS collector: `python -m unittest discover -s tools/news -p "test_*.py"`.

The output estimate of 1,024 tokens is a ranking scenario, not a spending cap. Actual output length, image pricing and cache hit rates may differ. Only returned usage is recorded as real tokens. Auto does not yet enforce a remaining monthly budget, learn quality/speed from measured history, or implement tool workflows. Provider capability/price entries still need live verification with team accounts. No paid provider calls or server deployments are performed by these tests.

## Android Studio acceptance steps

1. Open this repository, sync Gradle, run the debug build.
2. Configure two providers in Me → models/keys. In Chat's model picker open Auto preferences and try each preference. Reopen the app to check persistence.
3. Attach an image: text-only models should be unavailable. Send with Auto; inspect the chosen model/reason, then ask a text-only follow-up and check vision remains required.
4. Upload a text PDF: a text-capable model can summarise its extracted contents.
5. Choose a text-only model manually in an image conversation: confirm the app explains incompatibility, rather than switching silently.
6. Inspect Insights for returned usage and the new routing reason. Compare actual token/cost data with the labelled estimate; they need not match exactly.
7. Open Explore → Trending, select a topic, open a news article. Check reload/fallback handling on an unavailable publisher page.
